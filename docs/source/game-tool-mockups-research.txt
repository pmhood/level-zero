# Workbench — Frontend Design System & Implementation Specification

## Purpose

This document defines the frontend implementation standards for **Workbench**, an AI-native game-development workspace for turning early ideas into structured designs, visual assets, prototypes, and playable builds.

Use this specification as the source of truth when implementing new pages, components, and interactions.

Primary goals:

- maintain strong visual consistency across all tools
- avoid each page becoming its own mini-product
- preserve a cinematic, technical, game-development feel
- enable dense professional workflows without visual clutter
- support AI-assisted workflows naturally
- make reusable primitives the default
- minimize visual drift across generated implementations

# 65. Do / Don't

## Do

- use dark navy surfaces
- use thin borders
- use restrained accent colors
- use visual imagery generously
- maintain information density
- keep layouts purposeful
- reuse components
- treat AI as contextual
- link related entities
- preserve provenance

## Don't

- use pure black backgrounds
- use excessive glassmorphism
- over-round everything
- add neon glows everywhere
- turn the interface into Discord
- turn every screen into an AI chat
- use giant cards where density matters
- use marketing-site spacing
- create unique navigation for each tool
- introduce dozens of arbitrary colors

# 72. Definition of Done for UI Tasks

A UI task is complete when:

- it uses semantic color tokens
- it reuses shared components
- dark/light contrast meets accessibility requirements
- selected, hover, focus, loading, empty, and error states exist
- keyboard navigation works
- responsive behavior is defined
- inspector behavior is appropriate
- AI actions are visually distinct from deterministic actions
- entities link back to canonical project objects
- generated content preserves provenance
- no arbitrary design values are introduced without justification

# 73. Product-Wide Principle

Workbench is not a collection of generators.

It is a connected creative system.

A user should be able to begin with:

```txt id="3q1vbu"
"What if I made a game about scavenging abandoned spacecraft?"
```

and eventually move through:

```txt id="25hq8l"
Idea

↓ Explore

Design Pillars

↓ Develop

World
Characters
Mechanics

↓ Visualize

Moodboards
Concept Art
Character Sheets
Assets

↓ Define

Game Design Document

↓ Test

Playable Prototype

↓ Produce

Tasks
Code
Engine Assets

↓ Ship

Build
Playtest
Deploy
```

without losing the relationship between any of those artifacts.

The UI exists to make that progression feel natural.

## The implementation rule to preserve above everything else:

**Every object in Workbench should feel like part of the game, not part of the tool.**
:::

The next useful artifact would be a **page-by-page UX specification** for Home, Idea Lab, Moodboard, World, Characters, Mechanics, GDD, Prototype, Assets, and Build, including exact layout regions, interactions, menus, and what happens when you click each major control.
